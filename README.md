# Лист героя

Онлайн-лист персонажа D&D 5e (редакции 2014 и 2024). Идея взята у Long Story Short, но код, тексты и дизайн свои.

Что умеет:

- **Автоматика с ручным контролем.** Показатели считаются сами (КД, спасброски, навыки, СЛ заклинаний, ячейки), а по клику видно, из чего складывается число. Любую цифру можно задать вручную, но с подписью «за что получено», и всё попадает в журнал изменений.
- **Предметы, черты и мутации с эффектами.** Эффект меняет любой показатель: «+1 к КД», «Ловкость не меньше 19», сопротивление огню, владение навыком, преимущество. У предметов есть условия «надет», «настроен», «лежит в сумке». Мутации (части тела от других рас) устроены так же.
- **Формулы**: `1d4 + 2`, `13 + DEX`, `PROF * 2`. Работают в эффектах, атаках, счётчиках и прямо в тексте заметок, где броски кликабельны.
- **Заклинания.** Общая библиотека с dnd.su, свои заклинания и правки заклинания только для одного персонажа. Текущая концентрация всегда видна вверху листа.
- **Мультикласс.** Требования к характеристикам, урезанные владения второго класса, общая таблица ячеек, отдельные СЛ и атака для каждого класса-заклинателя. Окно повышения уровня показывает, что изменится: хиты, мастерство, ячейки, увеличение характеристик.
- **Подсказки при наведении** почти на всё: зачем нужен навык, из чего сложился бонус, откуда кости хитов и каждое вдохновение.
- **Счётчики** (рационы, рубины, заряды), несколько вдохновений с подписью «за что», отдых, состояния, истощение.
- **Лишние механики отключаются** в настройках: навыки (например, «Уход за животными», «Религия»), щит, монеты и прочее.
- **Вкладки** «Раса», «Класс», «Черты», «Мутации», «Лор», «Заметки» вместо одной длинной страницы. Журнал изменений (с поиском) и настройки открываются кнопками справа вверху. Удобный редактор текста с таблицами.
- **Импорт из Long Story Short** и выгрузка персонажа в JSON. Мастер создания персонажа: стандартный набор, покупка очков, броски.
- Вход по почте и паролю, через Google и Discord; способы входа подключаются друг к другу на странице «Аккаунт». Тёмная и светлая темы, телефон и компьютер.

Стек: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, PostgreSQL + Prisma 7, Better Auth, TipTap, Zustand, Zod. Тесты: Vitest и Playwright.

## Запуск на своём компьютере

Нужны Node.js 22 и PostgreSQL 16.

```bash
cp .env.example .env          # впишите DATABASE_URL и BETTER_AUTH_SECRET
npm install
npx prisma migrate deploy     # создаст таблицы
npm run dev                   # http://localhost:3000
```

Секрет можно получить так: `openssl rand -base64 32`.

Первый зарегистрированный пользователь становится администратором: ему доступна загрузка общей библиотеки заклинаний. Если нужно назначить конкретных людей, перечислите их почты в `ADMIN_EMAILS`.

## Деплой на Vercel + Neon

1. Создайте базу на [neon.tech](https://neon.tech) (подойдёт и Supabase или Vercel Postgres) и скопируйте строку подключения. В Neon берите вариант без `-pooler` в адресе: через него проходят миграции.
2. На [vercel.com](https://vercel.com) импортируйте этот репозиторий. Настройки сборки менять не нужно: Vercel сам запустит скрипт `vercel-build`, который применяет миграции и собирает сайт.
3. В Settings → Environment Variables добавьте:

   | Переменная | Значение |
   | --- | --- |
   | `DATABASE_URL` | строка подключения к базе |
   | `BETTER_AUTH_SECRET` | случайная строка, `openssl rand -base64 32` |
   | `BETTER_AUTH_URL` | адрес сайта, например `https://dnd-web.vercel.app` |
   | `ADMIN_EMAILS` | необязательно: почты администраторов через запятую |
   | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | необязательно, для входа через Google |
   | `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET` | необязательно, для входа через Discord |

4. Нажмите Redeploy, чтобы переменные подхватились.

Кнопки Google и Discord появляются, только когда заданы оба ключа провайдера.

### Вход через Google и Discord

- **Google**: [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → создайте проект → OAuth consent screen (External, название сайта, своя почта) → Credentials → Create credentials → OAuth client ID → Web application. В Authorized JavaScript origins укажите `https://ВАШ-АДРЕС`, в Authorized redirect URIs `https://ВАШ-АДРЕС/api/auth/callback/google`. Client ID и Client secret идут в `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`.
- **Discord**: [Discord Developer Portal](https://discord.com/developers/applications) → New Application → OAuth2. В Redirects добавьте `https://ВАШ-АДРЕС/api/auth/callback/discord`. Client ID и Client Secret (кнопка Reset Secret) идут в `DISCORD_CLIENT_ID` и `DISCORD_CLIENT_SECRET`.

Для локального запуска добавьте те же адреса с `http://localhost:3000`.

Как связываются аккаунты: вход через Google или Discord с той же почтой попадает в существующий аккаунт, только если почта подтверждена с обеих сторон. Аккаунт, созданный по почте и паролю, автоматически не склеивается (так чужой Discord с вашей почтой не получит доступ к персонажам): войдите по паролю и нажмите «Подключить» на странице «Аккаунт». Там же можно задать пароль аккаунту, созданному через Google или Discord.

## Деплой на свой сервер (Docker)

Нужны Docker и Docker Compose. Рядом с `docker-compose.yml` создайте `.env`:

```bash
DB_PASSWORD=...             # openssl rand -hex 24
BETTER_AUTH_SECRET=...      # openssl rand -base64 32
BETTER_AUTH_URL=https://ВАШ-АДРЕС
ADMIN_EMAILS=               # необязательно
GOOGLE_CLIENT_ID=           # необязательно, вход через Google
GOOGLE_CLIENT_SECRET=
DISCORD_CLIENT_ID=          # необязательно, вход через Discord
DISCORD_CLIENT_SECRET=
```

```bash
docker compose up -d --build
```

Поднимутся Postgres (данные в томе `db-data`) и сайт на `127.0.0.1:3010` (порт меняется через `APP_PORT`). Миграции применяются при каждом старте. Снаружи сайт открывают через обратный прокси с HTTPS, например nginx + certbot. Обновление: `git pull && docker compose up -d --build`.

## Заклинания с dnd.su

Страница «Заклинания» → «Загрузить с dnd.su» (видна администратору). Способов три, повторная загрузка обновляет заклинания, а не дублирует их:

1. **С сервера.** Сервер сам обходит страницы dnd.su небольшими пачками, вкладку нужно держать открытой. Если dnd.su не пускает сервер (защита от ботов), используйте второй способ.
2. **Через браузер.** Скопируйте скрипт со страницы импорта, откройте dnd.su/spells, вставьте скрипт в консоль разработчика (F12 → Console). Браузер скачает файл `spells-dnd.su-….json`. Скрипт только читает открытые страницы сайта.
3. **Файлом.** Загрузите этот файл в блоке «Загрузить файл». Большие файлы отправляются частями.

Свои заклинания может создавать любой пользователь, они видны только ему. Изменить заклинание для одного персонажа можно прямо в листе: правка не затронет библиотеку.

Библиотека dnd.su в репозиторий не входит: тексты принадлежат сайту, их загружает сам администратор.

## Перенос персонажа из Long Story Short

1. В Long Story Short откройте персонажа и скачайте экспорт (JSON).
2. Здесь: «Персонажи» → «Импорт», загрузите файл. Перед созданием покажутся итоговые КД, хиты и СЛ: их можно сверить с LSS.
3. В экспорте LSS заклинания записаны внутренними номерами без названий. После импорта на вкладке «Заклинания» нажмите «Сопоставить» и вставьте названия, например из PDF-версии листа. Строки «Заговоры» и «3 уровень» задают уровень тем заклинаниям, которых нет в библиотеке: они добавятся как свои, описание можно дописать.

## Проверки

```bash
npm run lint
npm run typecheck
npm test                 # модульные тесты: правила, формулы, импорт
npm run build && npm run test:e2e   # браузерные тесты, нужна база из DATABASE_URL
```

Те же проверки запускает GitHub Actions на каждый pull request (`.github/workflows/ci.yml`).

## Устройство

- `src/lib/rules` — модель персонажа (Zod), формулы, расчёт показателей с расшифровкой, справочные таблицы.
- `src/lib/import` — импорт из Long Story Short и разбор страниц dnd.su.
- `src/lib/server` — база, авторизация, API персонажей и заклинаний.
- `src/components/sheet` — лист персонажа: хранилище с отменой и автосохранением, вкладки, диалоги.
- `src/app` — страницы и API (`/api/characters`, `/api/spells`, `/api/auth`).
- `scripts/dndsu-export.ts` — браузерный скрипт выгрузки заклинаний.
- `e2e` — браузерные тесты Playwright.
